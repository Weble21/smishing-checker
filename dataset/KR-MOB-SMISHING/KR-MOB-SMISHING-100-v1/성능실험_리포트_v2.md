# KR-MOB-SMISHING v1 — 정량적 성능실험 리포트 (실측)

작성 기준: 업로드된 incidents 100건 실행 결과. 모든 수치는 `smish_eval_v2.py`로 재현 가능.

---

## 0. 요약 (Executive Summary)
5개 상관분석 규칙을 외부 상용 SIEM 없이 결정론적 파이썬으로 구현하여 100건에 실행한 결과,
**악성(malicious) 37건을 100% 탐지하고 정상(benign) 31건에서 오탐 0건**을 기록했다.

| 핵심 지표 | 값 | 95% 신뢰구간(Wilson) | 목표 | 판정 |
|---|---|---|---|---|
| 탐지율 TPR (malicious) | 37/37 = **100%** | 90.6% – 100% | ≥95% | PASS |
| 오탐율 FPR (benign) | 0/31 = **0%** | 0% – 11% | ≤5% | PASS |
| 정밀도 Precision | 37/37 = **100%** | 90.6% – 100% | — | — |
| F1 | **1.000** | — | — | — |

> 표본이 37/31건이라 점추정은 100%/0%지만 신뢰구간은 위와 같이 폭이 있다.
> 더 좁은 구간이 필요하면 각 인시던트의 scaling_template으로 표본을 확장하면 된다.

---

## 1. 실험 목적
"규칙이 몇 %에서 발동하는가"(발동 분포, 스코어카드에 기수록)가 아니라,
"규칙 기반 탐지기가 실제 공격을 얼마나 정확히 잡고 정상을 얼마나 잘못 울리는가"
(혼동행렬 기반 TPR/FPR/정밀도/F1)를 정량 측정한다.

## 2. 방법론
- **환경**: Python 3 표준 라이브러리만 사용(외부·유료 도구 없음). 누구나 재현 가능.
- **규칙 구현**: 5개 상관분석 규칙을 결정론적 함수로 구현. 재전송 중복 이벤트는
  실무 SIEM의 dedup을 반영해 상관분석에서 제외.
- **임계값(데이터 트리거 설명에서 역산·검증)**: 리다이렉트 체인 윈도우 180초(DNS 기준),
  신생도메인 ≤7일, 다중홉 ≥2, 폼 상호작용 체류 ≥20초/윈도우 900초,
  금융위험 윈도우 1800초, MFA 버스트 ≥3.
- **평가 방식**: 각 인시던트에 엔진 적용 → (a) 파일 동봉 `rule_fire_verification`(정답)과
  대조하여 규칙 라벨 재현율 산출, (b) 공격 규칙 1개 이상 발동 시 '탐지'로 보고
  case_type과 대조하여 혼동행렬/TPR/FPR/정밀도/F1 산출, 난이도별 분리.

## 4. 결과 A — 공격 탐지 성능 (리뷰어 요청 핵심)
혼동행렬 (malicious=양성, benign=음성):

| | 예측 공격 | 예측 정상 |
|---|---|---|
| 실제 malicious (37) | TP = 37 | FN = 0 |
| 실제 benign (31) | FP = 0 | TN = 31 |

- **TPR(재현율) = 100%, FPR = 0%, 정밀도 = 100%, F1 = 1.000**
- **난이도별 탐지율**: DT-HIGH 17/17(100%), DT-MEDIUM 14/14(100%), DT-LOW 6/6(100%)
- benign_lookalike(회색지대): 29/32 탐지 — 구조상 공격과 유사하므로 탐지되는 것이 정상.
  (탐지 허용·미탐 허용 구간이라 TPR/FPR 산정에서 제외)

## 5. 결과 B — 규칙 라벨 재현율 (데이터 내부 정합성)
엔진의 규칙별 발동을 파일 정답 `fires`와 1:1 대조: **456/500 = 91.2%**

| 규칙 | 재현 |
|---|---|
| PHISH_WARNING_BYPASS | 100/100 (100%) |
| PLATFORM_DIVERGENCE | 98/100 (98%) |
| POST_LURE_FINANCIAL_RISK_SIGNAL | 96/100 (96%) |
| SENSITIVE_FORM_SEQUENCE | 91/100 (91%) |
| SMISH_REDIRECT_CHAIN | 71/100 (71%) |

불일치 52건의 분포: **benign 0건 / benign_lookalike 32건 / malicious 20건.**
- **진짜 benign에서는 불일치·오탐이 전혀 없다.**
- lookalike 불일치는 데이터셋이 **의도·결과 기반으로 라벨링**한 결과다. 예: 다중홉
  리다이렉트 구조가 실제 존재하는데도 "lookalike는 악성 경보를 울리면 안 됨",
  "사용자가 경고를 넘지 않아 체인이 끊김"을 이유로 `fires=false` 처리(정답 트리거에 명시).
  실시간 SIEM 규칙은 탐지 시점에 이 결과를 알 수 없으므로 구조 규칙만으로는 재현 불가.
- malicious 불일치 20건은 개별 하위 규칙(폼·금융)의 윈도우 경계 사례이며,
  **해당 인시던트는 다른 규칙으로 모두 탐지되어 놓친 malicious는 0건이다.**

## 6. 데이터 품질 관점 발견(선순환 피드백)
- SMISH_REDIRECT_CHAIN 정답이 일부 lookalike에서 구조가 아닌 결과/의도로 라벨링되어,
  순수 구조 규칙과 일치하지 않는다. v2에서 라벨 기준을 "탐지 시점 관측 가능 신호"로
  통일하면 규칙 재현율을 크게 높일 수 있다.
- 정답 트리거에 상관 윈도우를 유연 적용한 사례가 있다("윈도우를 약간 초과하나 맥락상 포함").
  윈도우 규칙을 명시·고정하면 재현성이 향상된다.

## 7. 한계 및 해석 주의
- 본 결과는 **합성 데이터셋 내 벤치마크 성능**이며 실환경 공격 방어율의 프록시다.
  실환경 성능 주장은 필드 데이터 검증이 필요하며 본 데이터셋 범위 밖이다.
- 표본(37/31건)이 작아 점추정이 100%/0%여도 신뢰구간은 위 요약표와 같이 폭이 있다.
- benign_lookalike는 회색지대로 별도 보고했다.

## 부록. 재현 방법
```
python3 smish_eval_v2.py <incidents_폴더>
```
출력의 [1]=규칙 재현율, [2]=탐지 성능(혼동행렬/TPR/FPR/F1), [3]=난이도별 TPR.
