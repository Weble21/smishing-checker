# KR-MOB-SMISHING 학습 적합성 점검

판정: **문자 문맥의 보조 학습 자료로 조건부 사용 가능. 현재 학습에 자동 병합하지 않음.**

사용자 지정 기준: 실제 공식 도메인 여부는 운영 화이트리스트
`dataset/whiteList/official_domains.csv`로 조회한다. 학습 모델이 주소의 진위를
암기해 결정하게 하지 않는다. `message_context.py`가 화이트리스트 조회 결과와
문자에 언급된 기관의 일치 여부를 계산해 문맥 모델에 함께 전달한다.
따라서 KR-MOB-SMISHING에 실제 도메인이 없다는 점은 문맥 학습 자체를 막는 조건이 아니다.
다만 가상 정상 사례도 조회 결과가 '공식목록미확인'이 되므로, 원본 사건의 정상 라벨을
도메인 안전 라벨로 옮기지 않는다. 아래의 문자별 라벨 검토는 여전히 필요하다.

검사 대상은 `dataset/KR-MOB-SMISHING/KR-MOB-SMISHING-100-v1` 전체 사건 JSON이다.
2026-09-11 기준 `audit_kr_mob.py`로 검사했고 원본 파일은 수정하지 않았다.
재실행 결과는 `kr_mob_audit.json`, 재실행용 노트북은 `kr_mob_audit.ipynb`에 있다.

## 활용 범위와 제한

- **KoELECTRA 문맥 학습:** 인증 미완료, 서비스 중단, 업데이트 요구 등 표현을 학습하는
  보조 자료로 유용하다. 학습 입력은 워터마크를 제거한 문자와 그 문자에 실제 포함된 URL로 한정한다.
- **공식 기관/도메인 관계 학습:** 실제 기관·도메인이 제거된 합성 자료라 단독으로 불가능하다.
  기존 `brand_link_pairs.csv`와 공식 도메인 목록을 별도로 사용해야 한다.
  여기의 .example 도메인을 운영 화이트리스트에 추가하면 안 된다.
- **CANINE URL 모델:** 가상 도메인 90개만으로 실제 악성 URL 특성을 학습하려 하면
  합성 주소의 형식에 과적합할 수 있어 주 학습원으로 적합하지 않다.
- **실제 성능 평가:** 합성 100사건의 성능은 실제 탐지율의 근거가 되지 않는다.

## 병합 전 필요한 조치

1. **사건 결과와 문자 위험도를 분리한다.** `benign_lookalike`는 문서상 공격이 있었으나
   사용자가 중단한 사건이다. 정상(0)으로 자동 매핑하면 공격 문자를 정상으로 학습할 수 있다.
   위험(1) 후보로 검토하되 사건 안의 개별 문자까지 확인해야 한다.
2. **정상 라벨의 관찰 가능성을 검토한다.** `inc-MOB-BEN-005`는 업데이트하지 않으면
   서비스 중단이라는 문구와 가상 링크를 포함하지만 정상 사건이다. 정상 판단 근거는
   수신 후의 공식 사이트/앱스토어 이용 시나리오에 있다. 현재 앱의 문자+도메인 정보만으로는
   이 근거를 확인할 수 없다. 해당 종류는 검토 대기 또는 보류 평가 세트로 분리하고
   정상·위험 중 어느 쪽으로도 무조건 재라벨링하지 않는다.
3. **정답 누출을 막는다.** incident_id의 MAL/BEN, case_type, expected_rules,
   ground_truth, detection_cues, 송금 차단·페이지 입력·리디렉션 등 클릭 후 로그는
   문자 수신 시점 분류기의 입력으로 사용하지 않는다. 사건당 여러 문자는 동일 분할에 둔다.
4. **README 대신 실제 파일의 수를 기준으로 기록한다.** 차이는 확인됐으나 원인은 확인되지 않았다.
   표본 수정 이력이나 문서 갱신 여부를 확인할 필요가 있다.
5. **출처 정보를 유지한다.** 동봉 LICENSE.txt는 CC BY-NC 4.0과 출처 표시·비상업 조건을
   명시한다. 원본 출처, 가공 여부, 라이선스를 학습 manifest에 기록한다.

이 점검에서는 사건 시나리오의 사실성이나 모든 개인정보 마스킹을 보증하지 않았다.
104개 문자의 개별 라벨 검수와 실제 문자 테스트는 아직 수행하지 않았다.
